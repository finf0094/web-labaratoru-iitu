# Как защищать ПР6 — шпаргалка

## 1. Суть работы за 30 секунд

> «Я сделал небольшое, но реальное исследование одного компонента агентной AI-платформы — инструмента поиска (retrieval) для RAG на казахском языке. Я проверил три вещи: какой метод поиска лучше находит нужные тексты (RQ1), насколько легко злоумышленнику подсунуть агенту вредоносный текст через этот поиск (RQ2) и сколько стоит вызывать поиск через протокол MCP (RQ3). Данные — открытый датасет KazQAD: 1 929 настоящих вопросов ЕНТ и 100 000 абзацев казахской Википедии».

Главные цифры, которые надо помнить:

| Что | Число |
|---|---|
| Лучший метод | BM25 с обрезкой слов до 5 букв (prefix-5): nDCG@10 = **0.473** |
| Обычный BM25 по словам | 0.371 (prefix-5 лучше на 27 %) |
| Гибрид RRF | 0.459 — **не лучше** лучшего метода, но лучший Recall@100 = 0.859 |
| LSA | 0.032 — практически не работает |
| «Отравленный» текст в топ-5 | 96.5–100 % (копия вопроса), 69–95 % (половина слов) |
| Фильтр (guardrail) | ловит 100 % явных атак на EN/RU/KZ, **0 %** перефразированных; ложные срабатывания 0.35 % |
| MCP | +3.0 мс на вызов (3.8 → 6.8 мс) |

## 2. Как рассказывать по разделам

**Introduction.** Агенты = LLM в цикле «подумал → вызвал инструмент → посмотрел результат». Самый важный инструмент — поиск по документам (RAG). Казахский — агглютинативный язык (много суффиксов: *кітап, кітаптар, кітаптарымыздан*), поэтому точное совпадение слов плохо работает. Поиск ещё и канал атаки: indirect prompt injection (Greshake et al.). MCP — стандарт подключения инструментов. Отсюда три RQ и пять гипотез. Рисунок 1 — концепт-карта «теория → конструкт → переменная».

**Methodology.** Количественный вычислительный эксперимент, within-subjects: все методы отвечают на одни и те же вопросы, поэтому используются парные тесты. Выборка — все 1 929 тестовых вопросов (не выборка, а вся тестовая часть). Корпус уменьшен до 100 000 абзацев (все размеченные + случайные «отвлекающие», seed 42), чтобы всё считалось на ноутбуке за минуты. Параметры взяты из литературы и **не подбирались** на тесте — это защищает от подгонки. Статистика: bootstrap CI, Friedman, Wilcoxon с поправкой Holm, размер эффекта r. Всё воспроизводится одной командой `bash run_all.sh`.

**Results.** Только факты (таблицы 3–8, рисунки 4–7), без объяснений — так требует задание.

**Discussion.** Объясняем *почему*:
* prefix-5 склеивает формы одного слова → решает проблему суффиксов; то же самое известно для турецкого (Can et al., 2008);
* гибрид не помог, потому что RRF полезен, когда объединяешь *одинаково сильные* методы, а n-граммы слабее в начале списка;
* LSA — старый метод без обучения, 256 измерений слишком грубо; это **не** значит, что современные нейросетевые dense-ретриверы плохи — их мы не тестировали;
* поиск, который хорошо находит релевантный текст, так же хорошо находит текст злоумышленника, который копирует вопрос → поиск не защищает, найденный текст нужно считать недоверенными данными;
* regex-фильтр ловит только шаблонные фразы → нужна многоуровневая защита;
* MCP почти бесплатен по времени (3 мс намного меньше времени ответа LLM).

**Conclusion.** Рекомендации: prefix-5 BM25 по умолчанию; гибрид — как кандидаты для реранкера; найденный текст = недоверенные данные; не полагаться только на фильтры; MCP — единый слой интеграции.

## 3. Вероятные вопросы и ответы

| Вопрос | Ответ |
|---|---|
| Почему нет опроса / участников? | Это малый проект, который проверяет свойства программных компонентов; на них отвечают измерения, а не мнения. Опрос и интервью есть в общем плане исследования (ПР5) — следующий этап. |
| Почему 100 000, а не 825 000 абзацев? | Чтобы проект был «small-scale» и считался за минуты на обычном компьютере. Все размеченные абзацы включены, остальные — случайная выборка с seed. Из-за этого абсолютные значения выше, чем в статье KazQAD (0.389), поэтому сравниваю порядок методов, а не абсолютные числа. Это указано в ограничениях. |
| Что такое nDCG@10? | Качество первых 10 результатов с учётом позиции: релевантный документ на 1-м месте даёт больше, чем на 10-м. 1 = идеально, 0 = ничего полезного. |
| Почему разница 0.014 значима, если она маленькая? | Выборка очень большая (1 929 пар), поэтому даже маленькая разница значима. Поэтому я привожу размер эффекта: r = −0.12 — маленький эффект, практически методы близки. |
| Почему Wilcoxon, а не t-test? | Значения nDCG по вопросам не распределены нормально (много нулей и единиц), а сравнения парные → непараметрический парный тест. Holm — поправка на 7 сравнений. |
| Почему не нейросетевые эмбеддинги? | Ограничение малого проекта: в рамках работы использовались только методы без предобученных моделей. Это первое направление будущей работы. |
| Ваша атака реальна? | Это симуляция: я измеряю *exposure* — попадает ли вредоносный текст в контекст агента. Выполнит ли LLM инструкцию — следующий шаг с LLM в цикле. Адреса — example.com, атакуется только локальная копия. |
| Не подогнали ли вы фильтр под атаки? | Шаблоны писались по общим описаниям атак (OWASP, Greshake) до прогона; перефразированные атаки специально без «ключевых слов» — и фильтр их не поймал, что я честно показываю. |
| Почему ложные срабатывания? | 353 из 354 — e-mail адреса в статьях о коммунах Франции/Италии. Вывод: правило зависит от контекста, поэтому флаги надо передавать агенту, а не молча удалять текст. |
| Зачем MCP, если +3 мс? | Именно поэтому: цена мала, а выигрыш — один стандартный способ подключать инструменты к любому агенту. Важнее размер ответа (10 КБ → токены), его и ограничиваю. |
| Как повторить? | `bash run_all.sh` — все числа и рисунки пересчитываются; данные открытые. |
