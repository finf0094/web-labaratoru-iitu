# ПР6 — текст для защиты (~7 минут)

**[0:00 — Вступление]**
Здравствуйте. Моя шестая работа — отчёт по небольшому реальному эксперименту. Тема — какой поиск лучше использовать для RAG на казахском языке.

**[0:20 — Что такое RAG]**
Языковая модель не знает наших документов и иногда выдумывает факты. RAG решает это так: документы заранее режут на абзацы и индексируют. На вопрос пользователя поисковик находит подходящие абзацы, их добавляют в промпт, и модель отвечает по ним со ссылками на источники. Переобучать модель не нужно — достаточно обновить индекс.

Модель опирается только на то, что нашёл поиск. Если нужный абзац не найден, ответ будет неверным. Поэтому поиск — самое слабое звено RAG, и я исследовал именно его.

**[1:20 — Казахский язык]**
Казахский язык агглютинативный: кітап, кітаптар, кітаптарымыздан — это одно слово, но для компьютера три разные строки. Обычный поиск их не связывает. Для турецкого языка помогло простое решение — обрезать слова до пяти букв. Я проверил, работает ли это для казахского.

**[2:00 — Данные и методы]**
Данные — открытый датасет KazQAD от ISSAI Назарбаев Университета: тысяча девятьсот двадцать девять настоящих вопросов ЕНТ по пяти предметам и сто тысяч абзацев казахской Википедии. Для каждого вопроса известно, какие абзацы правильные.

Я сравнил пять методов: обычный BM25 по словам; BM25 с обрезкой слов до пяти букв; поиск по кусочкам слов; старый векторный метод LSA; и гибрид двух методов. Настройки взяты из статей, ничего не подгонялось.

Вопросов три: какой метод точнее, сколько абзацев давать модели и насколько быстро это работает. Главная метрика — nDCG@10, качество первых десяти результатов: единица — идеально, ноль — ничего полезного.

**[3:20 — Результаты]**
Лучший метод — BM25 с обрезкой: 0,473. Обычный BM25 даёт 0,371, то есть обрезка улучшила результат на двадцать семь процентов. Гибрид — 0,459, близко, но не лучше. Поиск по кусочкам слов — 0,327, LSA почти не работает. Тесты Фридмана и Уилкоксона показали, что различия значимы.

С пятью абзацами модель получает пятьдесят три процента нужной информации, с двадцатью — семьдесят один, со ста — восемьдесят пять. Поиск занимает меньше двух миллисекунд на вопрос.

**[4:30 — Почему так]**
Обрезка склеивает формы одного слова, поэтому вопрос находит абзац даже с другим окончанием. Гибрид не победил: склеивание рейтингов помогает, когда оба метода одинаково сильные, а второй был слабее. LSA — старый метод без обучения, и это не значит, что современные нейросетевые эмбеддинги плохие: их я не тестировал. Давать модели сто абзацев нет смысла: промпт становится длинным, а прирост маленький.

**[5:30 — Ограничения]**
Корпус уменьшен до ста тысяч абзацев, датасет один, нейросетевые модели и итоговые ответы модели не проверялись.

**[5:50 — Рекомендации]**
Для AI-платформы: по умолчанию использовать BM25 с обрезкой до пяти букв и давать модели десять–двадцать абзацев. Следующий шаг — нейросетевые эмбеддинги, реранкер и проверка на реальных документах университета. Всё повторяется одной командой, данные и код открыты. Спасибо, готов ответить на вопросы.
