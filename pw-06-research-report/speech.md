# ПР6 — текст для защиты (~4 минуты)

Здравствуйте. Моя шестая работа — отчёт по небольшому реальному эксперименту. Тема — какой поиск лучше всего использовать для RAG на казахском языке.

Что такое RAG. Модель не знает наших документов и иногда выдумывает. Поэтому документы заранее режут на абзацы и индексируют. На вопрос пользователя поисковик находит подходящие абзацы, их добавляют в промпт, и модель отвечает по ним. Если поиск не нашёл нужный абзац, ответ будет неверным, поэтому поиск — самое слабое звено, и я исследовал именно его.

Казахский язык агглютинативный, у одного слова много окончаний: кітап, кітаптар, кітаптарымыздан. Обычный поиск по словам эти формы не связывает.

Данные — открытый датасет KazQAD от ISSAI Назарбаев Университета: тысяча девятьсот двадцать девять настоящих вопросов ЕНТ и сто тысяч абзацев казахской Википедии. Для каждого вопроса известно, какие абзацы правильные.

Я сравнил пять методов: обычный BM25 по словам; BM25, где каждое слово обрезано до пяти букв, и «кітаптарымыздан» становится «кітап»; поиск по кусочкам слов; старый векторный метод LSA; и гибрид двух методов.

Вопросов три: какой метод точнее, сколько абзацев давать модели и насколько быстро это работает. Главная метрика — nDCG@10, качество первых десяти результатов: единица — идеально, ноль — ничего полезного.

Результаты. Лучший — BM25 с обрезкой: 0,473. Обычный BM25 даёт 0,371, то есть обрезка улучшила результат на двадцать семь процентов. Гибрид — 0,459, близко, но не лучше. LSA почти не работает. Различия статистически значимы: я проверял тестами Фридмана и Уилкоксона.

Сколько абзацев давать модели. С пятью абзацами модель получает чуть больше половины нужной информации, с двадцатью — семьдесят один процент. Поэтому рекомендую десять–двадцать. Поиск занимает меньше двух миллисекунд на вопрос.

Почему так. Обрезка склеивает формы одного слова; то же самое раньше показали для турецкого. Гибрид не победил, потому что второй метод был слабее. LSA — старый метод без обучения, и это не значит, что современные нейросетевые эмбеддинги плохие: их я не тестировал.

Ограничения: корпус уменьшен, датасет один, нейросетевые модели и итоговые ответы модели не проверялись.

Рекомендации для платформы: по умолчанию BM25 с обрезкой до пяти букв, десять–двадцать абзацев на ответ. Следующий шаг — нейросетевые эмбеддинги и реранкер. Всё повторяется одной командой. Спасибо, готов ответить на вопросы.
