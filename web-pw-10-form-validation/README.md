# Web Programming — Practical Work 10. Form Validation and Data Processing

**Язык:** Python 3.10+ и Flask (задание разрешает Java/Spring Boot, PHP или Python/Flask).
**Вся обязательная проверка выполняется на сервере**, в файле [`validators.py`](validators.py). HTML-атрибуты в задании 5 — только удобство для пользователя.

## Как запустить

```bash
cd web-pw-10-form-validation
pip install -r requirements.txt       # Flask
python3 app.py                        # открыть http://127.0.0.1:5000
python3 -m unittest discover tests    # 10 автотестов: все строки таблиц из задания и чек-лист
```

Скриншоты пересоздаются командой `pip install playwright pillow && python3 make_screenshots.py`. Скрипт сам запускает сервер, вводит все тестовые значения в Chromium и рисует над страницей адресную строку с настоящим URL.

## Задания

| № | Адрес | Правило | Сообщения |
|---|---|---|---|
| 1 | `/task1` | Имя обязательно; пробелы по краям убираются (`strip`) | `Name is required!` / `Welcome, Ali!` |
| 2 | `/task2` | Email не пустой и по формату (регулярное выражение) | `Valid email!` / `Invalid email!` |
| 3 | `/task3` | Возраст: заполнен → целое число → 18–100 включительно | `Age is required!`, `Age must be a number!`, `Age must be between 18 and 100!`, `Valid age!` |
| 4 | `/task4` | Все три поля сразу; **все** ошибки собираются в список, а не только первая | `Registration data is valid!` или список ошибок |
| 5A | `/task5` | Та же форма с атрибутами `required`, `type="email"`, `type="number" min max` | Браузер не даёт отправить форму |
| 5B | `/task5/without-html-validation` | Атрибуты убраны: неверные данные доходят до сервера | Сервер всё равно отклоняет |

Все формы отправляются методом **POST**. При ошибке сервер возвращает код **400**, при успехе — **200**.

## Чек-лист из задания — проверено тестами

| Проверка | Результат |
|---|---|
| Пустое имя | `Name is required!` |
| Имя из одних пробелов | `Name is required!` |
| Неверный email | `Invalid email!` |
| Возраст меньше 18 | `Age must be between 18 and 100!` |
| Текст вместо возраста | `Age must be a number!` |
| Все поля верные | `Registration data is valid!` |
| Несколько неверных полей | Показаны все ошибки сразу |

## Как защищать (коротко)

* **Почему проверка на сервере обязательна.** Браузерную проверку легко обойти: убрать атрибуты в DevTools или отправить запрос напрямую, например
  `curl -X POST -d "student=&email=x&age=abc" http://127.0.0.1:5000/task5`.
  Сервер не должен доверять ничему, что пришло от клиента.
* **`strip()` перед проверкой.** Иначе строка из одних пробелов считалась бы заполненной.
* **Формат email ≠ существующий ящик.** Проверить, что ящик существует, можно только письмом с подтверждением.
* **Порядок проверки возраста.** Сначала заполнено ли поле, потом число ли это (тип), потом входит ли в 18–100 (диапазон). Сравнивать с 18 можно только число.
* **Задание 4.** Каждое поле проверяется отдельно, а ошибки собираются в список. Пользователь сразу видит все проблемы, а не исправляет их по одной.
* **Вывод экранируется Jinja.** Введённый HTML показывается как текст (это проверяет тест `test_output_is_escaped`).
