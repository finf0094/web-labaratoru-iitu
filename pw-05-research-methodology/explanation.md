# Как защищать ПР5 — шпаргалка

## 1. Суть за 30 секунд

> «В ПР5 я превратил план исследования в детальную воспроизводимую методологию. Тема — проектирование и оценка агентной AI-платформы: LLM работает в цикле (agent loop), вызывает инструменты через MCP и отвечает по документам через RAG. Я сформулировал 5 исследовательских вопросов с проверяемыми гипотезами, выбрал Design Science Research со смешанными методами, обосновал выборки расчётом мощности, разработал инструменты (гайд интервью, анкету SUS/TAM, спецификацию датасетов, согласие) и спланировал анализ».

## 2. Пять RQ и гипотезы (выучить)

| RQ | О чём | Гипотеза | Чем проверяю |
|---|---|---|---|
| RQ1 | MCP vs ручная интеграция | MCP экономит ≥ 30 % времени разработчика | Парный t-test / Wilcoxon, 24–34 разработчика |
| RQ2 | Какой поиск лучше (BM25 / dense / hybrid) | Hybrid + reranking лучше | Friedman + Wilcoxon, ~300 вопросов |
| RQ3 | Дизайн agent loop | Agentic RAG успешнее single-shot RAG при < 2× токенов | McNemar, bootstrap |
| RQ4 | Защита от prompt injection | С guardrails ASR < 5 % | Wilson CI, ~200 атак |
| RQ5 | Удобство и полезность | SUS ≥ 68, TAM ≥ 5/7 | One-sample t-test, анкета |

## 3. Как объяснять ключевые решения

* **Почему Design Science Research?** Результат исследования — артефакт (платформа), который строится и оценивается итерациями (Hevner 2004, Peffers 2007).
* **Почему mixed methods?** RQ1–RQ4 — причинные эффекты → эксперименты и числа; RQ5 и объяснение ошибок → мнения людей → интервью и фокус-группы. Триангуляция повышает валидность.
* **Тип исследования по лекции (Kothari):** applied, empirical, analytical, mixed, decision-oriented; подходы — experimental, simulation, inferential.
* **Выборки:** вероятностная (стратифицированная случайная) там, где обобщаем на пользователей (опрос, n = 357 по формуле Кокрена для N ≈ 5000, ±5 %, 95 %); невероятностная (целевая, «снежный ком», удобная) там, где нужна глубина (12–15 интервью — насыщение по Guest et al., 2006). Числа считает `tools/sample_size.py`.
* **Валидность и надёжность:** валидированные шкалы (SUS, TAM), двойное кодирование 20 % интервью, фиксированные версии моделей и seed, 3 повтора прогонов, проверка LLM-судьи людьми (κ ≥ 0.7), предрегистрация плана анализа.
* **Этика:** информированное согласие, анонимность, только публичные документы и синтетические сервисы, атаки только на свои тестовые системы, закон РК о персональных данных.
* **Критерии хорошего исследования (лекция):** systematic, logical, empirical, replicable — в summary показано, как каждое выполнено.

## 4. Вероятные вопросы

| Вопрос | Ответ |
|---|---|
| Почему 357 респондентов? | Формула Кокрена: n₀ = 1.96²·0.5·0.5/0.05² ≈ 384, с поправкой на конечную совокупность N = 5000 → 357; при отклике 60 % рассылаем ~595 приглашений. |
| Почему 24–34 разработчика? | Power analysis для парного t-test: α = 0.05, мощность 0.8; d = 0.6 → 24, d = 0.5 → 34. |
| Почему ~200 атак? | Чтобы оценить долю успешных атак ≈ 5 % с точностью ±3 % при 95 % доверии. |
| Что такое SUS и TAM? | SUS — 10 вопросов об удобстве, балл 0–100, норма ≈ 68. TAM — воспринимаемая полезность и простота (Davis, 1989). |
| Что такое McNemar? | Тест для парных бинарных исходов (успех/неуспех одной и той же задачи двумя конфигурациями). |
| Как обеспечена воспроизводимость? | Публикуются код, конфигурации, датасеты, версии моделей; seed; план анализа фиксируется заранее. |
| Главные ограничения? | Один университет, быстро меняющиеся модели и протоколы, симулированные сервисы, студенты-разработчики вместо профессионалов. |
