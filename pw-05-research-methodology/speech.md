# ПР5 — текст для защиты (~5 минут)

**[0:00 — тема]**
Здравствуйте. Моя пятая практическая работа — это план и методология исследования. Тема: как подключать инструменты к LLM-агенту на AI-платформе — через протокол MCP или через библиотеку LangChain.

**[0:20 — что такое инструмент и агент]**
Сначала объясню основные понятия. Инструмент — это обычная функция, например «получить расписание группы» или «создать заявку в поддержку». Сама модель эту функцию не выполняет. Она видит название функции, описание и параметры и говорит программе: «вызови вот эту функцию с такими аргументами». Программа выполняет функцию и возвращает результат модели. Модель смотрит на результат и решает, что делать дальше: вызвать ещё один инструмент или уже ответить пользователю. Такой цикл — подумал, вызвал инструмент, посмотрел результат — называется agent loop, агентный цикл.

**[1:00 — два способа подключения]**
Подключить инструменты можно двумя способами.
Первый способ — LangChain. Это популярная библиотека на Python для создания агентов, вместе с LangGraph. Мы пишем функцию и ставим над ней декоратор `@tool`. Функция живёт внутри самого агента. Это просто, но если тот же инструмент нужен в другом приложении, код приходится копировать.
Второй способ — MCP, Model Context Protocol. Это открытый стандарт. Инструмент выносится в отдельный MCP-сервер, а любое приложение подключается к нему через MCP-клиент. Связь идёт через stdio, то есть как локальный процесс, или по HTTP. Главный плюс в том, что инструмент пишется один раз и используется в любом приложении. В LangChain такие инструменты подключаются библиотекой `langchain-mcp-adapters`.
Сама модель за агентом может быть облачной, а может быть своей, поднятой через vLLM или Ollama. Для моего исследования это не главное.

**[2:00 — исследовательские вопросы]**
У меня четыре исследовательских вопроса.
Первый — про трудозатраты. Если одни и те же три инструмента нужны в двух разных приложениях, быстрее ли подключить их через MCP, чем через `@tool`? Гипотеза: через MCP минимум на двадцать пять процентов быстрее.
Второй — про точность. Одинаково ли часто агент выбирает правильный инструмент с правильными аргументами через MCP и напрямую? И падает ли точность, когда инструментов становится двадцать, а не пять? Гипотеза: способы равны, а при двадцати инструментах точность ниже.
Третий — про скорость. Гипотеза: MCP добавляет меньше десяти миллисекунд на вызов, это меньше двух процентов от одного шага агента.
Четвёртый — про удобство для разработчиков. Его измеряю стандартным опросником SUS, где нормой считается шестьдесят восемь баллов.

**[3:00 — дизайн и выборка]**
Дизайн исследования смешанный, в основном количественный. Сначала идут измерения, потом короткие интервью, которые объясняют цифры. По классификации из лекции исследование прикладное, эмпирическое и аналитическое.
Главный эксперимент — с разработчиками. Каждый разработчик выполняет задание обоими способами, а порядок меняется, чтобы не влиял эффект обучения. Так каждый человек сравнивается сам с собой, и разница в опыте между людьми не мешает.
По расчёту мощности нужно двадцать четыре разработчика, набираю двадцать восемь с запасом на выбывание. Для точности — сто двадцать тестовых задач по три прогона, для скорости — тысяча замеров, интервью — двенадцать–пятнадцать.

**[4:00 — анализ, этика, ограничения]**
Время анализирую парным тестом, точность — тестом Макнемара, скорость — медианой и девяносто пятым процентилем, интервью — тематическим анализом. Гайд интервью, анкета, задания для разработчиков и форма согласия есть в приложениях, и перед основным этапом всё проверяется на пилоте.
Этика: участие добровольное, данные анонимные, все сервисы тестовые, персональные данные не используются.
Ограничения: один университет, студенты вместо опытных инженеров, библиотеки быстро меняются, поэтому версии фиксирую.

**[4:40 — вывод]**
Итог: методология систематичная, логичная, эмпирическая и воспроизводимая — это четыре критерия хорошего исследования из лекции. Она позволит понять, стоит ли использовать MCP как единый способ подключения инструментов в AI-платформе. Спасибо, готов ответить на вопросы.
